# Lattice 设计：文件、轨迹与学习地图

状态：方案，待确认后分阶段实施。

## 总体结构

```
 上面：操作和视觉
   各种意图（学一个东西、练、随手记、回顾、整理、读论文……）
   = 一种交互 + 一种视图 + 可选的 AI 代理
   视图 = 按属性和关系查出一组文件，用某种方式摆出来
 ─────────────────────────────────────────────
 中间：文件 + 基本属性 + 关系 + 学习轨迹 + 当前状态
   一套统一的操作：建、读、改、移、连、查、运行、回退、记轨迹
   学习者（界面）和 AI（工具）是这套操作的两个调用方
 ─────────────────────────────────────────────
 下面：就是文件
   学习库文件夹（默认 ~/Lattice/），git 仓库
```

判断标准：新功能先问能不能用中间的东西组合出来。需要新表、新通道或某个页面专用的后端逻辑时，说明中间缺了什么，应该补到中间，而不是补到功能里。

## 下面：学习库

```
~/Lattice/
  topics/<标题>.md            kind: topic
  cards/<标题>.md             kind: card
  lessons/<标题>.md           kind: lesson
  notes/<文件夹>/<标题>.md    kind: note
  insights/<标题>.md          kind: insight
  notebooks/<标题>.ipynb      标准 Jupyter 格式，属性在 metadata.lattice
  code/<主题>/…               任意源码：.py .js .c .cpp .rs .go .sh …，可以是多文件的小项目
  data/<主题>/…               数据和素材：.csv .json 图片 PDF …
  envs/<名字>.txt             Python 环境的定义（依赖清单）
  threads/<年-月>/<id>.jsonl  对话：首行是属性，之后每行一条消息
  journal/<年>/<年-月-日>.jsonl 学习轨迹，只追加
  .lattice/attrs/<id>.yaml    放不下 frontmatter 的文件（源码、数据、图片）的属性，进 git
  .lattice/venvs/<名字>/      按 envs/ 定义建出来的虚拟环境（不进 git，随时可重建）
  .lattice/runs/              每次运行的完整输出（不进 git，轨迹里只记摘要）
  .lattice/index.db           索引，可随时删除重建（不进 git）
  .lattice/state.json         当前状态（不进 git）
```

- 任何文件都是一等公民。能写 frontmatter 的（Markdown）写在文件里；notebook 写在 `metadata.lattice`；源码、数据、图片这类保持原样、干干净净，属性放在 `.lattice/attrs/` 的旁注里。外部拷进来或别的工具建的文件，第一次被引用、被打开或被运行时自动分配 id。
- 目录只是给人看的默认摆放，不承载含义；文件属于哪个主题、和谁有关，看属性和关系。

- 文件名给人看，引用一律用 `id`，改名、移动不会断链。
- 学习库是一个 git 仓库。每个 AI 动作提交一次，提交说明写明是谁、做了什么；学习者的编辑在保存或停顿时提交。撤销就是回退那次提交；回退冲突时提示，不强行覆盖。现在的动作表和笔记修订表由此取代。
- 外部编辑器改了文件，Lattice 监视到后更新索引，并按学习者的编辑处理。
- SQLite 只做索引：全文搜索、关系图、到期队列、轨迹查询。真实数据只在文件里。

### 基本属性

Markdown 用 frontmatter，notebook 用 `metadata.lattice`，线程用首行。所有文件只有这几个必备属性：

| 属性 | 含义 |
|---|---|
| `id` | 短编号，永不改变 |
| `kind` | topic / card / lesson / note / insight / notebook / code / data / thread；没写时按扩展名推断 |
| `title` | 标题 |
| `by` | 谁创建的：`me` 或某个代理（tutor、flash、coach、organizer） |
| `created`、`updated` | 时间 |
| `links` | 关系列表，见下 |

其余属性只在需要时出现，例如卡片的 `stage`、`due`，主题的 `question`、`route`。

### 关系

```yaml
links:
  - {to: t-7c1e, as: part_of}                    # 属于某个主题
  - {to: c-softmax, as: prerequisite, why: "…"}  # 前置
```

关系类型：`part_of`（属于主题或组成部分）、`prerequisite`、`related`、`applies_to`、`contrasts`、`derived_from`（这个文件由什么产生，比如练习线程来自哪段讲解）、`branch_of`（兴趣分支挂在哪条主线上）、`bridges`（一段绕路解释了主干上的什么）。正文里的 `[[标题]]` 也算 `related`。

### 所有权

所有权写在中间层的一张表里，只判断一次，不散落在各个功能中：

- 学习者独有：卡片的 `stage`，卡片正文中的「## 我的理解」一节，轨迹里 `actor: me` 的记录，回顾自评。AI 可以读，不能写。
- 删除只由学习者做。
- AI 写的东西学习者都能改、能撤销。

### 例子

```markdown
---
id: c-8f2a
kind: card
title: 为什么要除以 sqrt(d_k)
by: tutor
stage: explained
due: 2026-10-24
links:
  - {to: t-attention, as: part_of}
  - {to: c-softmax, as: prerequisite}
---
点积的方差随维度相加……

自测：为什么除数是 sqrt(d) 而不是 d？

## 我的理解
维度越高分数越胖，除根号 d 把尺度按回 1。
```

主题文件的正文就是主题档案（讲到哪、留下的疑问、接下来往哪走），`route` 是主干路线：

```yaml
question: 注意力到底在算什么，为什么能工作？
route:
  - {title: 加权平均, card: c-1a}
  - {title: softmax, card: c-softmax}
  - {title: Q/K/V}
  - {title: 位置编码}
```

路线由主讲维护，学习者可以直接改。节点没有卡片时只写标题。

## 中间：学习轨迹

轨迹是按天追加的 `journal/*.jsonl`，记的是学习这件事本身；文件内容的变化看 git。每条记录：

```json
{"at": "2026-10-21T14:23:05+08:00", "actor": "me", "type": "answered",
 "refs": ["t-attention", "c-softmax", "msg-…"], "data": {…}}
```

| type | 谁记 | data |
|---|---|---|
| `asked` | 应用自动 | 问题原文、所在线程、当时在看什么 |
| `answered` | 应用自动 | 学习者对任务或预测的回答 |
| `judged` | AI | 对某个回答的判断（对、部分对、错）和理由，标明是 AI 判断 |
| `explained` | AI | 讲了哪个概念、讲到什么深度 |
| `ran` | 应用自动 | 哪个单元格、是否成功、输出摘要 |
| `viewed` | 应用自动 | 看了哪个文件、停留多久（只记 30 秒以上的） |
| `wrote` | 应用自动 | 学习者写了或改了什么（我的理解、笔记、代码） |
| `staged` | 应用自动 | 学习者改了理解阶段 |
| `reviewed` | 应用自动 | 回顾自评 |
| `detour` | AI | 从主干哪个节点岔出去、为什么、岔路属于哪一类 |
| `bridged` | AI | 岔路结束：它和主干的什么接上了，一两句话 |
| `insight` | AI | 记下或划掉一个薄弱点、一个做得好的地方 |
| `organized` | AI | 整理了什么 |
| `installed` | 应用或 AI | 往哪个环境装了哪些包、因为哪次运行 |

AI 的判断只影响它对学习者位置的估计，永远不改学习者的理解阶段。

## 中间：当前状态

界面持续上报学习者此刻的状态（停顿时合并发送），保存在内存和 `.lattice/state.json`：

- 所在页面、焦点主题；
- 打开着的文件，以及视口里正在看的部分：Markdown 的当前小节、notebook 里可见的单元格、光标所在的单元格；
- 选中的文字；
- 小窗里正在写的内容（未关闭的草稿）；
- 最近看过的文件和停留时间（最近 20 个）。

AI 用 `screen` 工具随时读取。学习者发消息时仍然附一行界面附注。

## 中间：统一操作

界面的按钮和 AI 的工具调用同一组操作，校验和所有权检查只写一次：

| 操作 | 说明 |
|---|---|
| `create(kind, title, attrs, body)` | 新建文件 |
| `read(id)` | 读全文和属性 |
| `update(id, attrs?, body?, section?)` | 改属性、改正文或只改某一节，按所有权表检查 |
| `move(id, title?, folder?)` | 改名、移动 |
| `link(from, to, as, why?)` / `unlink` | 关系 |
| `query(kind?, attrs?, links?, text?)` | 按属性、关系、全文查 |
| `graph(scope?)` | 整张知识图：全部节点的 id、kind、title、所属主题、阶段、证据计数、最近活动，加全部关系和各主题路线 |
| `journal(filter)` | 读轨迹 |
| `record(type, refs, data)` | 写轨迹（AI 只能写 AI 那几类） |
| `run(id, cells?/args?)` | 运行任何可运行的文件，见下一节「运行与环境」；记 `ran` |
| `install(env, packages)` | 往某个环境里装包，并写回 `envs/<名字>.txt`；记 `installed` |
| `revert(commit)` | 撤销 |

AI 工具就是这组操作，加上 `screen`。位置不由程序计算：AI 读 `graph`、`journal` 和 `screen`，自己判断学习者在哪、该学什么、何时引导回主干，并据此设计讲解。

## 中间：运行与环境

目标是让学习者只管写、只管学：选哪个解释器、装什么包、怎么编译，都由 Lattice 处理。

**运行器是配置，按文件类型分派**，不为某种文件写专门的流程：

| 文件 | 怎么跑 |
|---|---|
| `.ipynb` | 该环境里的 Jupyter 内核，单格或全部运行，变量跨格保留 |
| `.py` | 该环境的 `python 文件.py`；matplotlib 的图自动保存并显示在输出里 |
| `.js` | `node` |
| `.c` `.cpp` | `gcc` / `g++` 编译到 `.lattice/runs/` 再运行 |
| `.rs` `.go` | `rustc` 编译后运行 / `go run` |
| `.sh` | `bash` |
| 对话里的代码块 | 存成对应语言的文件（属于当前主题、`derived_from` 那条消息），再按上面运行 |

- 运行都是本机的子进程：流式输出、可中断、有时限；工作目录是文件所在目录，所以同目录的数据文件、多文件的小项目都能直接用。
- 每次运行的完整输出存在 `.lattice/runs/`，轨迹记 `ran`：哪个文件、退出码、耗时、输出和报错的摘要。界面、AI 看到的都是这份真实输出。
- 运行器表可以加行（比如以后装了 Julia）。缺编译器或解释器时直接说缺什么、怎么装，不假装跑过。

**Python 环境由 Lattice 管理**（用 uv）：

- 学习库默认一个环境 `envs/default.txt`，首次使用时建好，预装 ipykernel、numpy、matplotlib；notebook 内核和 `.py` 都用它。
- 某个主题需要冲突的依赖时，给主题加属性 `env: <名字>`，它的文件就跑在自己的环境里。环境的定义是文件、可进 git；建出来的虚拟环境不进 git，换机器按定义重建。
- 运行报 `ModuleNotFoundError` 时，自动把对应的包（模块名和包名不同时由 AI 判断，如 sklearn → scikit-learn）装进这个环境、写回定义、重启内核，再重跑一次；装了什么记 `installed`，并在界面上一行显示，可以撤销（从定义里删掉并重建）。设置里可以改成装之前先问。
- 学习库外的项目目录（现在的「挂载目录」）作为外部目录接入：能看、能跑，有自己的 `.venv` 就用它的，没有就用默认环境；默认只读。

## 好奇心与主干

这部分写进主讲的规则，依据的全是上面中间层的东西：

- 学习者岔开时，主讲先判断岔路和主干的关系：主干的前置、当前节点的延伸、主干后面才会讲到的、无关的新兴趣。分别处理为：补到够用再回来；讲透再接回；先给直觉并指出它在路线的哪一站；跟着走，变成长线就建主题。
- 每次岔开记一条 `detour`，嵌套也记，所以总知道该回哪里。
- 提议回主干的参照：岔路的问题已经解决，或已经拿到它和主干的联系；岔路花的轮数明显超过它的分量；主干上有学习者没做的任务或预测；主干上有挡路的薄弱点。只用一句话提议，学习者想继续就继续。
- 一条岔路被反复深入时，升格为主题，用 `branch_of` 挂回主线。
- 每段岔路结束时必须说清它解释了主干的什么，记 `bridged`，并在图里加一条 `bridges` 关系。好奇心因此都变成地图上的边。

## 上面：视图和代理

- 任何文件都能在同一种编辑视图里打开：Markdown 有编辑和预览，源码有高亮、运行按钮和输出面板，notebook 是现在的单元格视图，数据文件给表格或图片预览。小窗就是这个编辑视图的缩小版，「写代码」时可以选语言，不选就由整理代理按内容起名和定扩展名。
- 现有页面都改成「查询加摆法」：知识卡页是 `kind=card` 按到期排；课程页是 `kind=lesson`；练习页是一个线程加一个 notebook 左右摆开；小窗是新建文件，关闭时交给整理代理；知识网络就是 `graph` 画出来。另外新增一个视图：主题路线图，标出各节点的证据状态、你在哪、挂着的岔路。
- 代理是配置：规则文本、可用的操作、模型连接。主讲、快答、练习教练、整理都是同一种东西的四份配置。以后加「论文导读员」只加配置。

## 分阶段实施

每一阶段都用真实模型，在从真实库复制出的隔离学习库上走完相关场景，再进入下一阶段。

1. **学习库核心**：文件格式读写（含旁注属性）、索引与重建、统一操作、所有权表、git 提交与回退、外部修改监视、迁移导出。界面暂不改，旧接口改为调用新操作。
2. **运行与环境**：运行器表、uv 管理的环境、notebook 内核切到托管环境、缺包自动安装、运行记录。
3. **轨迹与当前状态**：应用自动记录的那几类、AI 的 `record`、界面上报状态、`screen` 和 `graph` 工具。
4. **代理切到新操作**：工具改为统一操作，规则加入地图、路线和好奇心部分；四个代理改成配置。
5. **视图切到查询**：统一的文件编辑视图、现有页面改成查询加摆法、新增主题路线图。
6. **清理**：删除旧表和旧代码，更新 README 和现有检查。

## 风险

- 改动面大：每一阶段结束都保持可用，旧数据库全程保留。
- 外部编辑和应用内编辑同时发生：以文件为准，冲突时保留两份并提示。
- 学习库变大后 `graph` 会很长：先按主题范围返回，节点只给摘要，全文用 `read` 拉。
- 自动装包会联网并改动环境：只装进学习库自己的虚拟环境，不碰系统 Python；装之前按包名做一次存在性检查，记入轨迹并可撤销。
- 运行任意代码不是沙箱：和现在一样以学习者的用户权限运行，界面上明确标出。
