# Lattice 设计

状态：全部六个阶段已实施。实现上和下文不完全一样的地方，见文末「实施说明」。

## 核心想法

给 AI 足够的状态工具，让它随时知道两件事：我的学习状态（学过什么、卡在哪、在路线的哪里）和此刻的交互状态（开着什么、看到哪、在写什么）。AI 据此决定讲什么、给我看什么，并把它的判断写回状态。状态落盘成什么文件是实现细节，可以替换。

```
 界面：两个人，两类面板，布局由我自由安排
   AI 的面板：AI 给我看的一切都在它的输出里，我只读或做有限的交互
   我的面板：我自己深度处理的东西，AI 在这里只做辅助
 ─────────────────────────────────────────────
 AI 的工具，三层
   底层：命令行（关在沙箱里）——自己查看、分析、按规矩组织工作区里的内容
   Lattice 命令：固定格式的状态读写——知识图和路线、学习轨迹、我正在看什么、
                 在左边展示内容、在右边辅助我
   联网：搜索、抓取网页的接口，什么时候用由 AI 判断
 ─────────────────────────────────────────────
 状态
   学习状态：知识图、路线、轨迹、薄弱点
   交互状态：两块地方各开着什么、焦点、视口、选中、草稿
 ─────────────────────────────────────────────
 存储：学习库文件夹（默认 ~/Lattice/，git 仓库），可替换
```

判断标准：新功能先问能不能用现有的状态、命令和展示块组合出来。需要新表、新通道或某个页面专用的后端逻辑时，说明中间缺了什么，补到中间。

## 界面：两个人，两类面板

界面里只有两个使用者：我和 AI。面板按「归谁」分成两类，摆在哪里由我决定：所有面板都能拖动、分栏、叠成标签页、浮出、调整大小，布局会保存下来。下面说的「左边」「右边」只是默认布局。

**AI 的面板（默认在左边）。** AI 要给我看的东西都放在它的输出里：讲解、图、题、卡片、代码示例、搜索到的资料、对我右边内容的修改建议。我在这里只读，或者做有限的交互：

- 回答它出的题、做选择；
- 点开、展开、跳转（比如「在右边打开这个文件的第 3 节」）；
- 把它给的东西「拿到我这边」：代码示例变成我右边的一个文件，修改建议应用到我的文件里。

AI 的输出由一组展示块拼成，前端负责渲染。AI 不写 HTML，也不运行模型生成的脚本：

| 展示块 | 内容 |
|---|---|
| 正文 | Markdown，公式和代码块 |
| 代码示例 | 带语言标记，可以运行看结果，也可以拿到右边 |
| 题目 | 让我先预测或作答，答案直接记进轨迹 |
| 卡片组 | 一组卡片，可切到回顾模式；回顾自评由我点 |
| 图 | 知识图或某个主题的路线图，标出我在哪、挂着哪些岔路 |
| 表格 / 图表 | 对比、数据、实验结果 |
| 时间线 | 轨迹片段：这几天学了什么、卡在哪 |
| 文件摘录 | 学习库里某个文件的一段，带高亮，可以在右边打开到这里 |
| 修改建议 | 对我右边某个文件的改动，显示成差异，我点了才应用 |
| 资料 | 联网搜到的内容，带来源链接 |

**我的面板（默认在右边）。** 我自己深度处理的东西都在这里：打开的文件（笔记、代码、notebook、数据）、编辑器、运行和输出、文件浏览。每个文件一个面板，按我的习惯摆。

布局由我决定，AI 也能动手：它能打开、关闭、分栏、浮出面板，整个换一种布局，切换或新建工作区，收起左栏，改外观（`ui` 命令）。每次改动在它的回复下显示为一行，带「还原界面」，一键回到它动手之前的样子。它指给我看的东西默认放进我已有的同类面板。

AI 在我的面板里只做辅助，不抢主导：

- 打开文件、定位到某处、高亮某段，用来指给我看；
- 关窗后整理我写的东西（现在的小窗整理），或者我明确让它改的时候直接改；
- 其余对我文件的改动，都先以「修改建议」出现在左边；
- 我正在打字的地方，它不动；
- 它做的每一步都能撤销。

现在的「写代码 / 写记录」小窗、练习页的右半边、实验笔记页，都变成我的面板。练习不再是单独的页面：一个是教练的输出面板，一个是我的练习文件面板。可以同时开着好几个 AI 的面板（比如主讲和快答），各自一块。

## AI 的工具：三层

### 底层：命令行

AI 有一个命令行，用来自己查看、搜索、分析工作区里的内容，并按规矩组织文件：`ls`、`rg`、`cat`、`git log`、`python`，以及运行我的代码，都通过它。

- 用 bubblewrap 关在沙箱里：学习库可读写；我接入的外部项目目录只读；家目录其余部分、系统配置和各种凭据都看不到。
- 沙箱里不联网，联网只走第三层。
- 工作目录是学习库，Python 用学习库托管的环境。
- 每条命令都有时限，输出过长时截断，并告诉 AI 被截断了。
- 每轮 AI 动手之前，学习库先提交一次，所以命令行改坏了什么都能回退。

### Lattice 命令：固定格式的状态读写

结构化的状态必须走这一层，保证格式一致、所有权正确，并且界面会实时更新：

| 命令 | 作用 |
|---|---|
| `graph(scope?)` | 整张知识图：全部节点（id、种类、标题、所属主题、理解阶段、证据计数、最近活动）、全部关系、各主题路线 |
| `link` / `unlink` | 改知识图上的关系 |
| `route(topic, …)` | 改某个主题的主干路线：加、删、调整节点 |
| `journal(filter)` | 读学习轨迹 |
| `record(type, refs, data)` | 写轨迹（AI 只能写 AI 那几类，见下） |
| `insight` | 记下或划掉薄弱点、做得好的地方 |
| `screen()` | 我此刻的交互状态，见下 |
| `show(blocks)` | 在左边展示内容，用上面的展示块 |
| `ask(question)` | 在左边出一道题，等我作答 |
| `open(file, at?, highlight?)` | 在我的面板里打开文件并定位、高亮 |
| `ui(ops)` | 控制整个界面：开关、摆放、浮出面板，切换或新建工作区，收起左栏，改外观 |
| `suggest(file, change)` | 在它的面板里给出对我文件的修改建议 |
| `edit(file, change)` | 直接改我的文件（只在整理我写的东西，或者我明确要求时） |
| `run(file, …)` | 运行文件并取回真实输出，见「运行与环境」 |
| `install(env, packages)` | 往环境里装包 |
| `due()` | 到期要回顾的卡 |

### 联网

给 AI 两个接口：`search(query)` 搜网页，`fetch(url)` 读一个网页（转成正文）。什么时候需要查、查什么、信哪个来源，都由 AI 自己判断。

- 背后用哪家服务在设置里配：搜索 API、模型网关自带的联网能力，或者本机 LocalRouter，都可以接；接口不变，换服务不用改代理。
- 搜到的东西以「资料」块出现在它的面板里，带来源链接；用到的内容在讲解里注明出处。轨迹记一条 `searched`。
- 命令行沙箱本身仍然不联网，联网只走这两个接口，所以 AI 读到了哪些网页都有记录。

## 规矩

学习库根目录放一份规则文件，所有 AI 每轮都读：目录约定、属性格式、哪些必须用 Lattice 命令、所有权。

- 普通内容（笔记正文、代码、数据）可以用命令行直接改；知识图、路线、轨迹、我的理解阶段这类结构化状态，只能用 Lattice 命令改。
- 所有权在一个地方统一判断：卡片的理解阶段、「我的理解」一节、轨迹里我那一侧的记录、回顾自评，只归我。AI 能读，不能写。
- 命令行绕得过界面，所以每轮结束后，Lattice 用 git 检查这一轮改了什么：动到我独有的部分就自动退回那几处，并告诉 AI。
- 删除只由我做。

## 状态

### 学习状态

- **知识图**：所有内容和它们之间的关系，包括所属主题、前置、对比、应用，以及「这段岔路解释了主干的什么」。
- **路线**：每个主题的主干，就是一串关键节点。由主讲维护，我可以直接改。
- **轨迹**：按天追加，只记能作为证据的事。

| 类型 | 谁记 | 内容 |
|---|---|---|
| `asked` | 应用 | 我问了什么、当时在看什么 |
| `answered` | 应用 | 我对题目、任务、预测的回答 |
| `judged` | AI | 对我某个回答的判断和理由，标明是 AI 判断 |
| `explained` | AI | 讲了哪个概念、讲到什么深度 |
| `ran` | 应用 | 运行了哪个文件、成功与否、输出摘要 |
| `viewed` | 应用 | 看了哪个文件的哪部分、停留多久（30 秒以上） |
| `wrote` | 应用 | 我写了或改了什么 |
| `staged` / `reviewed` | 应用 | 我改了理解阶段 / 回顾自评 |
| `detour` / `bridged` | AI | 从主干哪里岔出去、为什么 / 岔路和主干接上了什么 |
| `insight` | AI | 记下或划掉薄弱点、做得好的地方 |
| `organized` | AI | 整理了我写的什么 |
| `searched` | AI | 搜了什么、用了哪些来源 |
| `installed` | 应用或 AI | 往哪个环境装了什么包 |

AI 的判断只影响它对我位置的估计，永远不改我的理解阶段。位置不由程序计算：AI 读知识图、轨迹和交互状态，自己判断我在哪、该学什么、什么时候引导我回主干。

### 交互状态

界面持续上报（停顿时合并发送），`screen()` 随时可读：

- 布局：开着哪些面板、怎么摆的、哪个在前台；
- AI 的面板：在看哪段对话、最近展示了什么、有没有没答的题；
- 我的面板：开着哪些文件、视口里是哪一节或哪几个单元格、光标在哪、选中了什么、没保存的草稿；
- 最近看过的文件和停留时间（最近 20 个）；
- 正在运行什么、最近一次运行的结果。

我发消息时，仍然附一行界面附注。

## 好奇心与主干

写进主讲的规则：

- 我岔开时，先判断岔路和主干的关系：主干的前置、当前节点的延伸、主干后面才会讲到的、无关的新兴趣。分别处理为：补到够用再回来；讲透再接回；先给直觉并指出它在路线的哪一站；跟着走，变成长线就建主题。
- 每次岔开记一条 `detour`，嵌套也记，所以总知道该回哪里。
- 提议回主干的参照：岔路的问题已经解决，或已经拿到它和主干的联系；岔路花的轮数明显超过它的分量；主干上有我没做的任务或预测；主干上有挡路的薄弱点。只用一句话提议，我想继续就继续。
- 一条岔路被反复深入时，升格为主题，挂回主线。
- 每段岔路结束时，必须说清它解释了主干的什么，记 `bridged`，并在图里加一条关系。好奇心因此都变成地图上的边。

## 存储：学习库（可替换）

```
~/Lattice/
  AGENTS.md                   规矩，见上
  topics/ cards/ lessons/ notes/ insights/   Markdown，属性在 frontmatter
  notebooks/                  标准 .ipynb，属性在 metadata.lattice
  code/ data/                 任意源码和数据，保持原样
  envs/<名字>.txt             Python 环境的定义
  threads/<年-月>/<id>.jsonl  对话
  journal/<年>/<年-月-日>.jsonl 轨迹
  agents/<名字>.md            可选：改写某个 AI 的工作方式
  .lattice/venvs/ runs/ kernels/ index.db state.json   可重建的东西（不进 git）
```

- 必备属性只有：`id`、`kind`、`title`、`by`（我或哪个 AI）、`created`、`updated`、`links`。其余按需出现，比如所属主题 `topic`，卡片的 `stage`、`due`，主题的 `question`、`route`、`threads`。主题文件的正文就是主题档案；练习是它那段对话头部的 `practice` 属性；AI 对已有卡片的补充直接写进卡片正文。
- 引用一律用 `id`；目录只是给人看的默认摆放，不承载含义。
- git 管历史和撤销：AI 每个动作提交一次，提交说明写明是谁、做了什么；我的编辑在停顿时、以及任何 AI 动作之前提交。撤销把那次提交改过的内容文件逐个改回提交前的样子，之后又被改过的文件算冲突、不覆盖；轨迹和对话只追加，不参与撤销。这取代了原来的动作表和笔记修订表。
- 外部编辑器改了文件，Lattice 监视到后更新索引，并当作我的编辑。
- SQLite 只做索引（全文搜索、关系图、到期队列、轨迹查询），删了能从文件重建。

## 运行与环境

目标是让我只管写、只管学。

- **按文件类型分派运行器**，运行器表就是配置：
  - `.ipynb` 用托管环境里的 Jupyter 内核；
  - `.py` 用托管环境的 python，matplotlib 的图自动显示在输出里；
  - `.js` 用 node；
  - `.c` / `.cpp` 用 gcc / g++ 编译后运行；
  - `.rs` 用 rustc 编译后运行，`.go` 用 go run；
  - `.sh` 用 bash。
  - 以后可以加行。缺解释器或编译器时直接说缺什么、怎么装，不假装跑过。
- 谁发起的运行，就用谁的权限：我在界面上点的运行以我的用户权限执行；AI 发起的运行（`run` 命令或命令行里）一律在它的沙箱里执行，不能借 `run` 绕出沙箱。需要联网的程序（比如下载数据集）由 AI 说明后，交给我来运行。
- 运行都是子进程：流式输出、可中断、有时限。工作目录是文件所在目录，所以同目录的数据文件和多文件的小项目都能直接用。完整输出存起来，轨迹记摘要，我和 AI 看到的都是真实输出。
- **Python 环境用 uv 托管**：学习库默认一个环境，首次使用时建好，预装 ipykernel、numpy、matplotlib；主题需要冲突的依赖时，可以用自己的环境。运行报缺模块时，自动把包装进对应环境、写回环境定义、重跑一次；模块名和包名对不上时由 AI 判断。装了什么记进轨迹，可以撤销；设置里可以改成装之前先问。
- 外部项目目录接进来后能看、能跑；它有自己的 `.venv` 就用它的，默认只读。

## 分阶段实施

每一阶段都用真实模型，在从真实库复制出的隔离学习库上走完相关场景，再进入下一阶段。

1. **学习库**（已实施）：文件格式读写、索引与重建、所有权、git 提交与回退、外部修改监视、迁移导出。
2. **运行与环境**（已实施）：运行器表、uv 托管环境、内核切到托管环境、缺包自动安装。
3. **状态**（已实施）：轨迹的自动记录、交互状态上报、`graph`、`journal`、`record`、`screen`。
4. **AI 的三层工具**（已实施）：沙箱命令行、Lattice 命令、联网接口（服务可在设置里配）；命令行之后的所有权检查；规则文件；四个代理改成配置，规则加入路线和好奇心部分。
5. **界面**（已实施）：可拖动、分栏、标签页、浮出的面板布局，并保存；AI 面板的展示块和有限交互；我的面板是统一的文件工作台（编辑、运行）；随手写、练习、实验笔记都是面板；路线图。
6. **清理**（已实施）：删除旧表和旧代码，更新 README 和现有检查。

## 风险

- 改动面大：每一阶段结束都保持可用，旧数据库全程保留。
- 命令行能力强：靠沙箱限制可见范围、不联网，每轮先提交、后检查所有权；出错就回退。
- 外部编辑和应用内编辑同时发生：以文件为准，冲突时保留两份并提示。
- 知识图变大后 `graph` 会很长：先按主题范围返回，节点只给摘要，全文用命令行或 `read` 拉。
- 自动装包会联网并改动环境：只装进学习库自己的环境，不碰系统 Python；装前确认包存在，记入轨迹，可以撤销。
- 我自己点的运行不是沙箱：以我的用户权限执行，界面上明确标出。AI 发起的运行都在沙箱里。

## 实施说明

代码的分层：`vault.py`（文件与 git）、`index.py`（SQLite 索引）、`model.py`（各类文件的含义与所有权）、`envs.py` 与 `runner.py`、`notebook.py`（运行与环境）、`sandbox.py`（沙箱）、`web.py`（联网）、`tools.py`（AI 的三层工具）、`agents.py` 与 `agents/*.md`（代理配置）、`bridge.py`（和界面之间的唯一入口与编排）。界面是 `ui/` 下的几个模块：`dock.js`（面板布局）、`spaces.js`（工作区）、`editor.js`（编辑器）、`notes.js`（笔记的管理、大纲与链接）、`chat.js` 与 `blocks.js`（AI 的面板和展示块）、`files.js`（文件工作台）、`panels.js`（学习库、知识图、轨迹、回顾、卡片库、记忆、设置）、`app.js`（启动、事件、交互状态上报）。

和上文不一样、或者上文没说清的地方：

- **展示块写在回复里。** `show` 和 `ask` 不是工具：AI 在回复里写语言标记为 `lattice:<类型>` 的代码块（内容是 JSON），界面渲染成题目、卡片组、图、图表、时间线、文件摘录；块里只写引用，数据由界面自己去取。这样展示块能随回复流式出现，也不多一轮工具调用。修改建议和资料来源由 `suggest`、`web_search`、`web_fetch` 工具记下，显示在回复下面。
- **源码和数据文件按路径引用。** 没有 `.lattice/attrs/`：它们需要的关系写在文档的 `links` 里（`file:<路径>`），活动从轨迹里来。
- **环境按目录选择。** 目录里放一个内容是环境名的 `.lattice-env` 文件，下面的文件就用那个环境，不是挂在主题上。挂载目录有自己的 `.venv` 就用它的。
- **实验笔记的内核默认在沙箱里。** 我和 AI 在同一个内核里运行，变量不会分成两份；内核在沙箱里才能让 AI 也运行它。需要联网或读我自己的文件时，我可以把这本笔记的内核切到我的权限，这时 AI 不能在里面运行。其余文件仍然是：我点的运行用我的权限，AI 发起的在沙箱里。所有内核都通过学习库里的 unix socket 连接，不开 TCP 端口。
- **沙箱还把 Lattice 自己的记录设为只读**：`threads/`、`journal/`、`AGENTS.md`、`agents/`、`.lattice/`（包括环境），所以命令行既改不了历史，也不能往我之后会不经沙箱运行的环境里放东西。所有权检查在每条命令之后做，而不是每轮结束后。
- **装包。** AI 发起的安装只装预编译的 wheel，不在本机执行包自己的构建代码。撤销一次安装会改回环境定义，环境在下次使用时跟着定义卸掉多出来的包。「装之前先问」就是关掉自动安装：运行结果里给一个「装上再运行」的按钮。
- **冲突。** 文件在外面被改了、而我这边还有没保存的修改时，界面让我选「载入新版本」或「保留我的」，不自动生成两份文件；两个版本都在 git 历史里。
- **浮出**是应用窗口里的悬浮窗口，可以拖回任何一组标签。
- **AI 可以控制整个界面**（后来的决定，取代上文最初的「AI 不移动我的面板」）：`ui` 命令按顺序执行一串界面操作，界面执行后把真实结果和当时的面板清单交回给它；动手之前的界面存成快照，回复下的「还原界面」回到快照（快照只在这次运行里有效）。
- **工作区**：活动栏上的每个图标是一个工作区，即一套默认提供的窗口组合，各有自己的内容和安排；左栏放这个工作区自己的列表，列表按「心智」分——主题（我在学什么）、知识卡（我懂了什么）、笔记（我写了什么）、课程（讲过什么）、实验与代码（我在做什么）、练习与薄弱点（我做得怎样）、全部文件、搜索——而不是一棵混在一起的文件树。对话工作区是会一直变化的主界面，什么窗口都能放，由 AI 按需要安排；知识卡工作区有自己的卡片库、回顾和记忆；其余几个是「左栏列表 + 一块放打开的东西 + 快答或主会话」。我可以改它们、隐藏它们，也可以自己搭新的。
- **窗口在工作区之间共享，不各自复制。** 同一个对话、同一个文件在几个工作区里是同一个窗口，所以对话是共同的；每个工作区只记自己怎么摆。关掉标签只是把它拿出这个工作区，没有哪个工作区再显示它时才真正关掉。每个工作区的左栏各自收起（右上角的按钮、再点一次图标或 Ctrl+B）。属于某个列表的入口放在列表顶上，活动栏底部只剩搜索、轨迹、开始页、明暗和设置。底部状态栏显示当前主题、谁在工作、沙箱状态。
- **数据的接口和面板无关。** 每一类东西（主题、知识卡、笔记、课程、薄弱点、实验笔记、练习、对话、文件、挂载目录、环境）都有同一个目录接口（`Bridge.catalog` / `Lattice.catalog`）：左栏、开始页和 AI 的 `list` 命令都从它取，「到期」这类判断只在后端算一次。界面只决定显示什么；AI 要知道学习库里有什么，查这个接口，不看面板。
- **对话面板是一栏可读的正文。** AI 的回复不套框，我的话是右侧气泡；时间、复制和「开始练习」这类按钮在悬停时出现；AI 做的事折叠成一行，要我马上处理的（还原界面、请主会话接住）留在外面。正文限宽（按正文字数算，设置里可选窄、中、宽、不限），笔记和课程的预览用同一个宽度。还没说话时输入框在中间，下面是从目录接口取来的几个起点。输入框一行时是胶囊，需要多行时变成圆角矩形；左边附上文件（只把路径交给 AI，它需要时自己读），右边是这个窗口用的模型，可以只为这个窗口换一个，跟着窗口记住。
- **模型的思考过程**随回答一起流过来：回答前和每一轮工具调用前想了什么，都存进那条消息（`thinking` 和用时）。默认折叠成一行「思考了 N 秒」加思考内容的第一句（摘要直接取自思考本身，不再多调一次模型）；思考进行中这一行滚动显示最新一句。设置或对话的 ⋯ 菜单里可以改成默认展开或不显示。历史对话只把回答发回给模型，思考不进历史。
- **选中的文字只是界面状态**，不会自动进任何对话（AI 用 `screen` 能看到）。「问快答 / 问主会话」只把它放进那个输入框，问题由我写；取消选中就清掉。
- **对话右上角的 ⋯ 菜单**放这段对话的其余功能：这个窗口的大小、行距、阅读宽度（按字数调）、输入框样式（胶囊或线条，快答默认线条）——只改这个窗口，跟着窗口记住；所有窗口的思考过程显示、正文和代码字号、密度、明暗；开新会话、提炼知识卡、换这个窗口的模型、复制整段对话、存成笔记、打开主题页、浮出、关闭。
- **大小分三层**：全局的正文字号、代码字号和行距；每种面板一个默认比例；每个窗口还能单独调（Ctrl + 滚轮、Ctrl + = / - / 0、标签右键），单独调过的跟着窗口记住，标签上显示百分比。缩放作用在整个面板上，文字、代码、间距和图标一起变。AI 的 `ui` 也能调某个窗口的大小。
- **主讲在界面上叫「主会话」**，其他 AI 也这么称呼它；代码和这份文档里仍叫 tutor / 主讲。
- **笔记按 Obsidian 的方式写和管。** 编辑器是 CodeMirror 6（`ui/vendor/codemirror.js`，打包进程序，不联网）：Markdown 默认实时预览，光标所在处才露出符号；`[[链接]]`（含别名和小节）、`#标签`、待办勾选、嵌入图片、表格、数学公式（KaTeX，`ui/vendor/katex/`）都在原地渲染，`[[` 和 `#` 有补全。管理都在文件上：文件夹树里新建、改名、拖动移动、收藏、日记、模板；改名时后端把所有指向它的 `[[链接]]` 一起改掉（代码里的不动），所以链接按标题写也不会断。笔记旁边的「大纲与链接」面板跟着正在看的那篇：大纲、反向链接（含提到却没链接的）、出链、标签，都从后端的目录接口算（`note_links`、`tags`），AI 和界面看到的是同一份。显示方式（实时预览、源码、分屏、阅读）和原文放在文件的 ⋯ 菜单里，默认的那种在设置里，页面上不放一排按钮。代码用同一个编辑器：高亮、彩虹括号、括号配对、Tab 跳出右括号、缩进、补全、折叠、查找替换。
- **弹出来的东西一个样子**：菜单、窗口、提问框、提示条、补全列表和查找栏共用同一套圆角、阴影和淡入；要确认或要填一个名字时用程序自己的提问框（Enter 同意、Esc 取消、删除类用红色按钮），不弹系统的 confirm / prompt。
- **设置**能改所有东西，改了就自动保存（文本框停下打字后保存）：外观与交互（主题、字号、行距、阅读宽度、密度、每种窗口的大小、发送键、选中弹出）、工作区与左栏（切换、改名字图标和左栏列表、调顺序、隐藏或删除、把现在的样子设为默认、恢复默认、新建；左栏宽度）、四个 AI（连接、模型、上限、temperature、带多少历史、能用哪些工具、规则全文——改了存进学习库的 `agents/<名字>.md`）、模型连接、联网、运行与环境（运行器表、每个 Python 环境的定义和安装、沙箱路径）、学习库（位置、挂载目录、导入导出）、学习库的规矩（AGENTS.md）、快捷键一览。界面偏好和工作区的定义在本机配置里，每个工作区现在的样子在学习库的本机状态里。
- **代理配置。** 四个 AI 的规则在 `lattice/agents/<名字>.md`（开头的属性写工具清单和读多少条历史，正文是规则）；学习库里放一份同名文件就替换它。每轮的系统提示依次是学习库的 `AGENTS.md`、这个 AI 的规则、展示块说明，以及一行身份：日期、这段对话属于哪个主题、练习的依据。
- **默认对话**不是一个主题：它就是不属于任何主题的那些对话（`topic` 为空）。
- **联网的地址检查**拒绝本机和局域网地址；代理软件的 fake-IP 网段（198.18.0.0/15）放行，否则开着代理时什么网页都读不了。
