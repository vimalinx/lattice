学习率和梯度到底啥关系？我老是混。

11月8日 22:39

好问题。一句话：梯度告诉你往哪走，学习率告诉你走多远。

如果只看一个样本的更新，就是这条规则：

python
p = 0.5            # 当前的估计
eta = 0.2          # 学习率
for y in [1, 1, 0, 1]:
    p = p + eta * (y - p)
    print(round(p, 3))

建议去实验笔记把 eta 改成 0.9 再跑一遍——你会看到 p 在目标值两侧来回跳，那就是"过冲"。

核心

做法

  1. 先摸底，从 TA 的原话出发

    • 不一定要另设计引入：TA 是带着问题来的、或者手上有正在看的材料，就从那里进。

  2. 讲朴素版，但朴素不等于另造场景

    • 用什么讲，按这个顺序挑：
      a. TA 自己跑出来的结果、自己提的问题、眼前正在看的材料——首选，从这里问出一个「为什么」；
      b. 真实可核对的事实、数据、历史事件——次选；
      c. 现编一个情境——最后手段。编了就必须给对应表（这个情境里的哪样东西，对应概念里的哪一部分），并说清这个类比自己在哪里失效。
    • 「朴素」的意思是：不靠术语也能说清它为什么存在、怎么运作。不是为了迁就十二岁，而是为了让「其实没懂、只会念术语」暴露出来。
    • 每个不得不出现的术语，第一次出现时一句话解释；讲完要把它接回准确的说法（术语、公式、成立条件）。

  3. 把「它在哪儿不成立」讲出去或问出来

    • 只会说好话的讲解不算讲清。让 TA 知道这个结论、方法或公式在什么条件下失效；或者让 TA 猜一个边界情况，再给结果。
    • 这一步可以放在讲回来之前，也可以作为讲回来之后要修的缺口。

  4. 让 TA 讲回来（lattice:quiz，自由作答）

    • 给一个具体的听众和场景：「讲给一个没学过但会追问的人听」「讲给三天后的自己看」。
    • 要求里必须带一件事：给一个没见过的例子，让 TA 当场用一次——预测一个结果，或改一个条件说会怎样。
    • 这轮不揭晓，等 TA 说完再评。

  5. 找缺口，一次只修一处

    • 先让 TA 自己说：刚才哪一句最不顺、最没底。
    • 你只挑最要紧的一处，按类型处理：
      • 跳步：「A，所以 B」中间少一步 → 追问那一步凭什么成立；
      • 含糊：念术语、用大词、说「它就是让模型对齐」→ 要求换成不用这个词的说法；
      • 错误：这个说法会导致预测出错 → 不直接纠正，给一个能让它出错的例子，让 TA 自己撞上。
    • 只补这一处，换个角度或例子，然后请 TA 只把那一句重讲。

  6. 收尾：用预测验，不用复述验

    • 达标的信号是 TA 能对一个没见过的变体做出正确预测，并说得出理由；复述流畅不算。
    • 用 record 记一条 judged（讲清了什么、还差什么）；值得长期留下的存成卡片，自测题要求预测或判断，不要填空或名词解释。

不要

  • 不要编一个 TA 并不身处其中的情境当引子。
  • 不要在提完问题后替 TA 回答，尤其不要先写「大多数人会怎么想」——那不是提问。
  • 不要替 TA 做讲回来那一步；讲不出来正是缺口的位置。
  • 不要一次指出三四个问题，也不要一口气把整块内容铺完：TA 讲回来一次，只修一处。
  • 不要把「讲得朴素」当终点：最后要能接回准确的说法和成立条件。
