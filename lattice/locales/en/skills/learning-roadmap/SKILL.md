# How
1. **Constraints**: the deadline, how much time is available each week, what level they need to reach (can use it / can explain it / can pass an exam on it). Estimate anything the learner hasn't said from the usual case, and state in the plan that it's an estimate.
2. **Estimate the size**: start from the topic's route (read the topic; if there is no route yet, lay one out first following the tutorial-tree skill), and estimate the time for each stop (explanation + practice + review). If the total is too much, first cut the directions that are there only out of interest, then downgrade some stops to "awareness only", and tell the learner what was cut.
3. **Lay out the weeks**: each week 1 to 3 stops, one hands-on exercise and one card review, with 20% left as slack; keep the last stretch before the deadline for an overall review.
4. **Write it down**: with save_knowledge's notes (folder `计划`, "plans"), write "<topic> study plan", one section per week: the goal, the stops to learn, how it will be checked, and `- [ ]` to-dos. In the topic's file, note in one sentence where the plan is and which week they're on now.
5. **Follow up**: from then on, before each session, check against the plan and the journal and say in one sentence where this week stands; if they're behind, reschedule rather than cramming.

# Don't
- Filling the schedule with no slack.
- Scheduling only "reading": every week needs an output that can be checked.
