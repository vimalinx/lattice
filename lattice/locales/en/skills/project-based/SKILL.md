# When to use
- “I want to build an X to learn Y”, “I've learned the theory and want hands-on practice”.
- Halfway through a topic, when several stops' worth of knowledge needs to be tied together and used.

# Steps
1. **Choose the project**: together with the learner, choose a project that can be finished in 3–8 study sessions, and write down clearly: what it looks like when done (a result that can be demonstrated), which stops on the route it uses, and what it won't do (the scope boundary).
2. **Split it into milestones** (3–6): each milestone = an intermediate result that runs and shows an effect + the points of knowledge it needs. Build the smallest version that runs first, then add features one at a time.
3. **Each milestone goes like this**:
   - First teach (or review) the knowledge this milestone needs;
   - Open a practice with start_practice (in lesson, write the key teaching points this step uses; in goal, write this milestone's acceptance criteria), and let the Practice coach take them through it;
   - After the practice, debrief (the practice debrief steps), and move on to the next milestone only once the acceptance criteria are confirmed as met.
4. **Write it down**: with save_knowledge's notes (folder “项目”), write a project description: the goal, the list of milestones (`- [ ]`), and each milestone's acceptance criteria and the knowledge it uses. Each time one is completed, tick it with edit and write one sentence on what was achieved.
5. **Wrap up**: when the project is finished, ask the learner to explain the structure of the whole project and its hardest step; save what was learned in the project that holds up apart from the project as cards.

# Don't
- Don't choose a project that takes three months to finish.
- Don't write the project code for the learner; you can give a skeleton, but they write the key parts themselves.
