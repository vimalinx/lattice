# When to use
- “What methods are there in field X now”, “Which of A, B and C should I pick”, “Look into X for me”.

# Steps
1. **Set the question** ⏸ Checkpoint: the questions the survey must answer, what it's for (learning, choosing a technology, writing a report), the time range, and the depth.
2. **Search**: use web_search with several different keywords (Chinese and English, synonyms, “survey”, “benchmark”, “vs”); read the original text of key sources with web_fetch. For what's already in the vault, use search and read. For each item, note down: source, date, key points, credibility (paper / official docs / blog / forum).
3. **Classify**: sort the methods or options into a few groups by their core idea (3–6 groups), and for each group state its representative works, core idea and where it fits. Draw a classification diagram (mermaid mindmap or flowchart).
4. **Compare**: one comparison table, with dimensions chosen for the survey's purpose (effectiveness, cost, maturity, ecosystem, learning curve…); every cell needs a basis.
5. **Conclusion**: give recommendations by purpose, and say under what conditions a recommendation would change. Say plainly where you're unsure.
6. **Save it**: with save_knowledge's notes (folder “调研”), write the survey (with links to all sources); for directions worth going deeper into, build them into a topic or branch following the tutorial-tree skill.

# Don't
- Don't rely on a single source; important conclusions need at least two independent sources.
- Don't take the summaries in search results as conclusions; read the originals.
- Mark outdated information with its date.
