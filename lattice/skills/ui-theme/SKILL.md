# 什么时候用
学习者想改界面的配色、字体或风格。只改字号、行距这类单项时用 ui 的 set，不用这个技能。

# 要做到的
- 整套协调：底色、面板、卡片、边框、三档文字、强调色、AI 色、代码高亮是一个家族，不是只换一两个颜色。
- 看得清：正文对底色、面板的对比度至少 4.5，次要文字至少 3；强调色上的字也要够。ui 工具返回的 warnings 就是在提醒这个，改到没有为止。
- 层次分明：bg、panel、panel-hi、surface 之间要有能看出来但不刺眼的差别；line 比 surface 再深（浅色主题）或再亮（深色主题）一点。
- 强调色和 AI 色要分得开：一个是「你的操作」，一个是「AI 的东西」。
- 代码高亮在新底色上仍然好读，关键字、字符串、函数、注释彼此区分得开。

# 做法
1. 不清楚想要什么感觉时，问一句（冷 / 暖、深 / 浅、活泼 / 沉稳，或者参照某个软件）；已经说清就直接做。
2. 先定两三个基准色（底色和一个主色相），其余颜色从它们推出来：同色相调明度做层次，强调色取对比色或同色系更饱和的一档。
3. 用 ui 工具 `{"do": "theme", "name": "<起个名字>", "base": "dark 或 light", "vars": {...}, "note": "一句话说明"}` 一次套上整套。风格（圆角、阴影、间距）用 css 写，选择器写具体（如 `.btn`、`.modal`、`.skill-card`），不要用 `[class*=...]` 这种一网打尽的写法；shadow 写完整的 box-shadow。
4. 看返回的 warnings，有就调到没有。
5. 回复里一两句话说这个主题的思路和主要颜色，告诉学习者不满意可以点「还原界面」，或者说哪里要改。

# 不要
- 不要只改一两个颜色就交差，界面会一半新一半旧。
- 不要用 url()、@import 或外部字体。
- 学习者正在专心学的时候不要主动改界面。
