# 什么时候用
- 学习者第一次接触一个概念、公式、算法或方法。
- 学习者说「从零开始」「开始吧」「讲这一站」，或者说「我不知道为什么要这样」。
- 你发现自己正准备一上来就写出公式或定义。

# 为什么按这个顺序
人只有在想解决一个问题时，才会去抓住答案；只有能挂到已知上，新东西才留得住；工作记忆一次只装得下几样；自己想过、猜过的才记得牢。下面的顺序就是照这几条排的，讲法可以变，顺序别乱。

# 做法（一轮只走一两步，走完就把思考交回去）
1. **问题**：用一个学习者能想象的具体场景，引出一个用现有办法解决不了、或者让人好奇的问题。只说问题，不给答案。最后问 TA：「你会怎么办？」（`lattice:quiz` 自由作答）。
   - 例：讲「学习率」之前——「你在猜一枚硬币正面朝上的概率，先猜 0.5；扔一次是正面，你会把猜测改成多少？改成 1 合理吗？」
2. **从已知出发**：看 TA 的回答，找到 TA 已经有的直觉（「改一点，但别全信这一次」），明确说出「你这个直觉就是我们要的东西」。
3. **小例子，让规律冒出来**：用能手算的数字走两三步。每走一步之前，先让 TA 猜下一步是多少，再算给 TA 看（能写代码的用 write + run 拿真实结果）。不要提前把整张结果表摆出来。
4. **起名字、写公式**：规律已经被 TA 看到以后，才说「这件事有个名字，叫……」，再把刚才的做法写成公式，每个符号对应刚才例子里的哪个数。
5. **检验**：出一道换了条件、只靠理解才能答对的题。答对了，这一点才算站稳。
6. **再往下**：一个点站稳了，才引入下一个新东西（比如它在哪里失效、换个参数会怎样），每一个都重新走「问题 → 猜 → 看 → 起名」。
7. **最后才连起来**：和后面内容的联系，学会以后用一句话点出，不提前铺垫。

# 不要
- 不要以公式、定义或代码开头。
- 不要在学习者还不知道为什么需要它时，就讲它的组成部分。
- 不要一轮里引入三个以上的新概念或新符号。
- 不要把该让学习者预测的结果先展示出来。
- 不要用「看出来了没？」这类反问代替真正的提问；要问就用 `lattice:quiz` 让 TA 作答。
- 粗体每轮最多一两处。
