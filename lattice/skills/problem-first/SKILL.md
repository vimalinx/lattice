# 什么时候用
- 学习者第一次接触一个概念、公式、算法或方法，还不知道它要解决什么。
- 学习者说「从零开始」，或者说「我不知道为什么要这样」。
- 你正准备一上来就写出公式、定义或代码。

动机已经清楚的时候（学习者自己带着问题来、刚撞上这个困难）不用这个技能，直接讲。

# 要做到的
- 新东西出场之前，学习者已经感到有个问题需要它。
- 这个问题落在 TA 能想象、能算的具体东西上，而不是一句「为了优化目标」。
- 新东西作为这个问题的答案出现，学习者能说出「原来它是为了解决……」。

# 让问题被感到的几种办法（选一种，按概念和学习者挑）
- **一个场景**：TA 能想象的情形里，自然冒出一个要做的决定。例：一个只有一个数的模型去猜温度，猜错了，下一次该怎么改？
- **旧办法失败**：先让 TA 用已经会的办法试，看着它在哪里不行。例：想直接令 p = y，结果一个噪声样本就把之前的全抹掉了。
- **一个反常现象**：一个和直觉不符的结果，让人想知道为什么。例：学习率调大以后反而学不会了。
- **一个要比较的选择**：两种做法都说得通，到底选哪个、凭什么。
- **TA 自己的问题**：从 TA 之前问过、卡过的地方接上（用 conversation 和 journal 找）。

# 和其他思路怎么配
问题立住以后，答案用什么思路讲，由概念决定：
- 是个公式或算法 → 让 TA 拿小数字算一两步（图解与逐步追踪），规律出来了再写成公式。
- 是个抽象机制 → 用类比建立直觉（先直觉后形式）。
- 有个常见误解 → 让 TA 先预测（误解探测）。
- TA 有基础 → 用追问让 TA 自己走到答案（苏格拉底追问）。

# 不要
- 不要把问题铺得比答案还长；一个问题、几句话，立住就够。
- 不要用「看出来了没？」这类反问代替真正的提问；要 TA 想就用 `lattice:quiz` 让 TA 作答。
- 不要每一站都用同一个场景套路；办法要换。
