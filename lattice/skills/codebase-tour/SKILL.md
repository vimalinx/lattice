# 什么时候用
- 「帮我读懂这个项目」「这个库是怎么工作的」「我要给这个项目贡献代码」。
- 代码在学习库里或挂载的目录里（挂载目录只读，用 read 和 shell 里的 rg、ls 看）。

# 阶段
1. **全景**：用 shell（ls、rg、wc、git log）看目录结构、语言、规模、依赖、最近改动多的地方。画一张模块关系图（mermaid），每个模块一句话说它干什么。
2. **入口和主流程** ⏸ 检查点：找到程序入口（main、CLI、服务启动、测试入口），沿一个最典型的使用场景追踪调用链，画成 sequenceDiagram；关键函数用 `lattice:excerpt` 指给学习者看原文。
3. **核心数据结构**：找出贯穿全局的几个数据结构或类，说清每个字段的含义、谁创建、谁修改。
4. **逐个深读**（每个关键模块一轮）：讲它的职责、接口、内部实现的要点、和别的模块的约定；请学习者预测某个函数在某个输入下的行为，再用 run（能跑的话）验证。
5. **动手验证** ⏸ 检查点：设计一个小改动（加一个打印、改一个行为、写一个测试），学习者在自己的副本里改并运行，确认理解对了。挂载目录只读，改动放在 `code/<项目名>/` 下的副本或实验笔记里。
6. **导读笔记**：用 save_knowledge 的 notes（folder 为「生产/<项目名>」）写一篇导读：全景图、主流程图、核心数据结构表、每个模块的要点、阅读顺序建议、常见坑。重要的设计思想存成卡片。

# 进度文件（复杂生产都用它）
复杂生产跨好几次对话，靠一个进度文件接续：
- **开始时**：用 save_knowledge 的 notes（folder 为「生产/<项目名>」）建一篇「<项目名> · 进度」，按附带的 progress-template.md 写：目标、阶段清单（`- [ ]`）、每个阶段的产出物路径、已经做出的决定、待学习者确认的问题。
- **每完成一个阶段**：用 edit 打勾，写上产出物的路径、这一阶段做了什么决定、验证结果。
- **每次接着做**：先用 search 或 list notes 找到进度文件并 read，从第一个没打勾的阶段继续；告诉学习者「上次做到哪、这次做什么」。
- **检查点**：标了「⏸ 检查点」的阶段做完要停下，把产出给学习者看、等 TA 认可或修改，再进下一阶段。不要一口气跑完所有阶段。

# 不要
- 不要一个文件一个文件地平铺讲；先全景，再顺着主流程深入。
- 不要猜代码的行为；能跑就跑，不能跑就读原文并标出依据的行号。
