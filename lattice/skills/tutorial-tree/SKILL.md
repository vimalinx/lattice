# 什么时候用
- 「我想学 X」「X 该怎么学」「从哪里开始」「给我列个学习路线」。
- 一个主题越聊越大，需要把它理成有结构的路线。

# 做法
1. **弄清目标和起点**（不超过三个问题，能从 graph、list、journal 看出来的就不问）：学了要用来做什么；现在会什么；每周大概多少时间。
2. **拆树**（先在心里，再写出来）：
   - **根**：这个领域要解决的核心问题。
   - **主干**：从入门到目标，按先后依赖排的 5～12 站。每一站是一个能在一两次学习里讲完、并且能检验的单元，写清「学完能做到什么」。
   - **分支**：从主干某一站岔出去、可以晚点学或者按兴趣选的方向（2～6 条）。
   - **先修**：哪些站必须先学哪些站（不是顺序上的先后，而是不懂就学不下去的依赖）。
   - 每一站标三个东西：要掌握的核心概念、一个检验方式（能回答的问题或能做出的东西）、建议的讲法（可用的技能，如 worked-examples、visual-trace）。
3. **对照已有**：用 graph 和 list 看学习库里已有的主题、卡片、课程；已经学过的站标「已掌握」或「接触过」（依据理解阶段和轨迹证据，不是猜），能复用的用 ref 指过去。
4. **给学习者看**：回复里用 ```mermaid flowchart 画出整棵树（主干一条线，分支挂在旁边，已掌握的站用不同样式），下面用 附带的 tree-template.md 的格式列出每一站。问 TA 要不要调整（太深、太浅、顺序、想加的分支）。
5. **落进学习库**（学习者认可以后）：
   - 主干：没有主题就 create_topic（question 写领域的核心问题，route 写主干）；已有主题就用 route 整条写入。每站的 why 写「学完能做到什么、为什么在这一站」。
   - 分支：每条分支用 create_topic 建成子主题（parent 是主干主题），question 写这个方向要回答的问题，route 先写 3～5 站。
   - 先修关系：站与站之间、已有卡片之间的依赖，用 link（kind=prerequisite）连上。
   - 用 update_topic 在主题档案里写一段「怎么用这棵树」：从哪一站开始、每站怎么检验、什么时候岔出去。
6. **标出现在在哪**：最后用 `lattice:graph`（topic 为主干主题，here 为当前这一站）给 TA 看，然后直接开始讲第一站。

# 不要
- 不要列一堆书名和网址代替结构；树的每一站都要可学、可检验。
- 站不要太粗（「学会深度学习」）也不要太碎（「了解 ReLU 的名字」）。
- 没有证据不要把站标成已掌握。
