# 什么时候用
- 要掌握的是一个**步骤性的方法**：解一类题、做一种推导、写一种代码结构、调一类 bug。
- 学习者是初学，直接让 TA 做会卡死。

# 做法
1. **完整例题**：选一道典型题，把每一步写出来，每步旁边写**为什么这样做**（不只是做了什么）。最后总结这类题的通用步骤（3～6 条）。
2. **对照题**：给一道结构相同、数字或细节不同的题，请 TA 先说出第一步该做什么（`lattice:quiz`）。
3. **渐退**：
   - 第 2 题：你写好前面大半，留最后一两步给 TA。
   - 第 3 题：只写开头一步，其余 TA 来。
   - 第 4 题：完全独立。
   每题都先让 TA 作答，再讲评。代码题用 `write` 写出骨架（关键行留 `___`），让 TA 补；用 `run` 看真实结果。
4. **变式**：最后给一道改了条件、需要稍微变通的题，检验 TA 是真会了方法还是记住了样子。
5. 用 record 记每道题 TA 在哪一步需要帮助；整理出的通用步骤可以用 save_knowledge 存成课程。

# 不要
- 不要只给例题不让 TA 做；也不要一开始就让 TA 独立做。
- 撤掉帮助要随 TA 的表现：哪一步还错，就在那一步多留一题。
