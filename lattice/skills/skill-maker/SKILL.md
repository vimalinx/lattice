# 什么时候用
- 「把这个做法存成技能」「我想要一个专门 X 的技能」「下次都按这个流程来」。

# 做法
1. **弄清这个技能管什么**：什么情况下该用（触发条件要具体）、要做出什么、给谁用（主会话、快答、练习教练、整理，哪几个该用它）。最好有一两个真实的例子（刚才那段对话就是例子时，用 conversation 读出来）。
2. **写清做法**：
   - 步骤按顺序编号，每步写做什么和为什么；
   - 写清用 Lattice 的哪些工具落地、产出放在哪里；
   - 有检查点的标出来；
   - 写「不要」：这类事最容易犯的错。
   长的模板、清单、例子放成附带文件（和 SKILL.md 放在同一个文件夹），在正文里写「照附带的 xxx.md」。
3. **写文件**：用 write 写 `skills/<英文短名>/SKILL.md`，开头的属性块：
   ```
   ---
   name: <英文短名，和文件夹同名>
   title: <中文名>
   description: <一句话：什么时候该用它（这句话会给 AI 看，用来判断该不该用，要写具体）>
   category: <讲解思路 / 课程与教程 / 练习与评估 / 复杂生产 / 研究与阅读 / 笔记与整理 / 其他>
   agents: [tutor, flash, coach, organizer]（只留该用它的）
   version: 1
   ---
   ```
   正文就是做法。附带文件也用 write 写进同一个文件夹。
4. **试一次**：请学习者在技能商城里看一眼，然后用一个真实的请求试用（在输入框的「＋」里选这个技能），按效果再改。

# 不要
- description 不要写空话（「一个很有用的技能」）；要写清什么情况下用。
- 不要把一次性的具体内容写进技能；技能是可以反复用的做法。
