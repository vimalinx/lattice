# 什么时候用
- 「帮我做一套 X 的完整教程」「把这个主题做成一门课」「写一个从零到一的系列」。
- 产出要成体系、要多章、要能复用，一次对话做不完。

# 阶段
1. **定位** ⏸ 检查点：读者是谁（会什么、不会什么）、学完能做什么、篇幅（几章、每章多长）、形式（讲义 + 代码 + 练习？）、风格。写进进度文件的「目标/范围/约束」。
2. **教程树** ⏸ 检查点：照技能 tutorial-tree 的做法拆出章节树（主干 = 章，分支 = 选学章），每章写清学完能做到什么、检验方式。用 create_topic / route 落成主题和路线（每章一站）。
3. **章节大纲** ⏸ 检查点：每章列出小节、每节的核心概念、要用的例子、要用的讲法（可参考 feynman、analogy-first、worked-examples、visual-trace）、本章练习的设计。写进进度文件。
4. **逐章成稿**（每章一轮，每章做完都是一个检查点）：
   - 按 lesson-writer 的结构写这一章；
   - 每段代码先用 write 放进 `code/<项目名>/第N章/`，用 run 真跑，输出贴进讲义；跑不通就修到能跑，不能把没跑过的代码放进教程；
   - 用 save_knowledge 的 lessons 存成课程，标题「第 N 章 · <章名>」；用 route 把这一站的 ref 指向它；
   - 本章的核心知识点用 save_knowledge 存成卡片（card-distill 的标准）。
5. **练习**：每章 3～6 道分级练习（problem-set 的分层），答案和讲解折叠在 `<details>` 里，追加到章节讲义末尾；需要动手的设计成可以用 start_practice 开的练习，并在讲义里写上练习目标。
6. **通读修订** ⏸ 检查点：把所有章节 read 一遍，检查：
   - 前后术语是否一致、符号是否统一；
   - 每章是否只用到了前面章节讲过的概念（发现前向引用就调整顺序或补一节）；
   - 难度曲线是否平滑；例子是否重复；
   - 所有代码都跑过（进度文件的验证记录里有）。
   列出问题清单给学习者，确认后逐条修改（edit）。
7. **总目录**：用 save_knowledge 的 lessons 写一篇「<教程名> · 目录」：简介、读者、怎么用、每章一句话 + [[链接]]、先修关系图（mermaid）。用 update_topic 在主题档案里写上教程的状态。

# 进度文件（复杂生产都用它）
复杂生产跨好几次对话，靠一个进度文件接续：
- **开始时**：用 save_knowledge 的 notes（folder 为「生产/<项目名>」）建一篇「<项目名> · 进度」，按附带的 progress-template.md 写：目标、阶段清单（`- [ ]`）、每个阶段的产出物路径、已经做出的决定、待学习者确认的问题。
- **每完成一个阶段**：用 edit 打勾，写上产出物的路径、这一阶段做了什么决定、验证结果。
- **每次接着做**：先用 search 或 list notes 找到进度文件并 read，从第一个没打勾的阶段继续；告诉学习者「上次做到哪、这次做什么」。
- **检查点**：标了「⏸ 检查点」的阶段做完要停下，把产出给学习者看、等 TA 认可或修改，再进下一阶段。不要一口气跑完所有阶段。

# 不要
- 不要一次生成全部章节；逐章做、逐章验证、逐章给学习者看。
- 不要放没运行过的代码和没核对过的事实；拿不准的标出来写进「待学习者确认」。
- 不要让后面的章节默默依赖前面没讲过的东西。
