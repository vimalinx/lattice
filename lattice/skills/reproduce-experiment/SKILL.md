# 什么时候用
- 「复现这篇论文的表 2」「照着这个教程跑出一样的结果」「验证这个说法对不对」。

# 阶段
1. **声称是什么** ⏸ 检查点：用一两句话写清原文声称的结果（具体到数字、图、条件），要复现到什么程度（趋势一致 / 数值接近 / 完全一致），算力和时间的限制。沙箱不联网、只有 CPU 时，提前说明能复现到哪一步。
2. **最小环境**：在实验笔记（write_cell）或 `code/<项目名>/` 里搭环境；缺的包用 install。先跑一个最简单的冒烟测试（能导入、能跑一步）。
3. **最小版本**：先复现一个缩小的版本（小数据、少步数、小模型），确认流程通、结果的方向对。每一步用 run 拿真实输出，不靠想象。
4. **对齐细节**：列出原文所有可能影响结果的细节（数据处理、超参数、随机种子、评估方式），逐项对齐；原文没写的，写下你的选择和理由。
5. **对比** ⏸ 检查点：把复现结果和原文并排（表格或 `lattice:chart`），说明哪些一致、哪些不一致、可能的原因。不一致不要硬调到一致；把原因分析写清楚。
6. **复现报告**：用 save_knowledge 的 notes（folder 为「生产/<项目名>」）写复现报告：声称、环境、做法、结果对比、偏差分析、结论、复现步骤（别人照着能跑）。学到的方法和坑存成卡片。

# 进度文件（复杂生产都用它）
复杂生产跨好几次对话，靠一个进度文件接续：
- **开始时**：用 save_knowledge 的 notes（folder 为「生产/<项目名>」）建一篇「<项目名> · 进度」，按附带的 progress-template.md 写：目标、阶段清单（`- [ ]`）、每个阶段的产出物路径、已经做出的决定、待学习者确认的问题。
- **每完成一个阶段**：用 edit 打勾，写上产出物的路径、这一阶段做了什么决定、验证结果。
- **每次接着做**：先用 search 或 list notes 找到进度文件并 read，从第一个没打勾的阶段继续；告诉学习者「上次做到哪、这次做什么」。
- **检查点**：标了「⏸ 检查点」的阶段做完要停下，把产出给学习者看、等 TA 认可或修改，再进下一阶段。不要一口气跑完所有阶段。

# 不要
- 不要报告没有真实运行过的结果。
- 不要为了「复现成功」挑选种子或偷偷改评估方式；改了就写出来。
- 跑太久的任务先缩小规模，不要一上来就跑满。
