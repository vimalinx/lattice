# 什么时候用
- 刚讲完一站，学习者通过了检验，想要一份可以回看的讲义。
- 学习者说「把刚才讲的整理一下」。

# 做法
1. **收集材料**：用 conversation 读这段讲解的对话，用 journal 看作答和运行记录。只用实际讲过、学习者实际回应过的内容。
2. **按这个结构写**：
   - **一句话**：这一课要弄懂什么（objective）。
   - **为什么需要它**：它解决的问题，不懂它会卡在哪。
   - **核心讲解**：从直觉到准确的形式；公式用 $…$ / $$…$$；关键图用 mermaid。
   - **完整例子**：至少一个从头到尾的例子；代码例子必须是真跑过的（用 run 验证，贴真实输出）。
   - **常见误解**：学习者这次真的犯过的错误优先（有证据的），每个配一句纠正。
   - **自测**：3 道题（预测、解释、应用各一），答案折叠在 `<details>` 里。
   - **下一步**：主干的下一站是什么。
3. **保存**：用 save_knowledge 的 lessons 存成课程（标题用这一站的名字），文中提到的已有卡片用 [[标题]] 链接；用 route 把这一站的 ref 指向这份课程。
4. 回复里只说一两句：存成了什么、放在哪。

# 不要
- 不要补写对话里没讲过的大段新内容；讲义是整理，不是另写一本书。
- 代码例子没跑过就不要放进去。
