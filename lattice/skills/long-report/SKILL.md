# 什么时候用
- 「帮我写一份 X 的技术报告 / 设计文档 / 调研报告」。
- 篇幅超过两三千字、需要论证和证据，一次对话写不完。

# 阶段
1. **问题与读者** ⏸ 检查点：这篇要回答的一个核心问题、读者是谁、读完要能做出什么判断、篇幅和格式要求。
2. **材料**：
   - 学习库里的：search、list、read 找相关的笔记、卡片、课程、实验记录；
   - 外部的：web_search / web_fetch（如果需要），每条材料记下出处；
   - 实验数据：只用真实运行过的结果（read 运行记录或 run 重跑）。
   把材料清单（来源 + 一句话要点 + 可信度）写进 `notes/生产/<项目名>/材料.md`（用 write）。
3. **提纲** ⏸ 检查点：论点式提纲——每一节一句话写出这一节要证明什么，下面列支撑它的材料。没有材料支撑的论点标出来。
4. **分节起草**：一次写一两节，写进 `notes/生产/<项目名>/正文.md`（用 write 首次创建，之后用 edit 追加或改写某一节）。每个事实性论断都要能对上材料清单里的一条；数据和图表用真实结果（`lattice:chart` 可以先给学习者看）。
5. **核对** ⏸ 检查点：通读全文，检查：
   - 每个论断有没有出处；数字有没有和来源一致；
   - 节与节之间有没有矛盾、重复、跳步；
   - 术语前后一致；结论是否超出了证据。
   把问题列给学习者，确认后修改。
6. **成稿**：写摘要（三五句话说清问题、方法、结论）、整理参考文献；需要的话导出版本另存。在进度文件里记下终稿路径。

# 进度文件（复杂生产都用它）
复杂生产跨好几次对话，靠一个进度文件接续：
- **开始时**：用 save_knowledge 的 notes（folder 为「生产/<项目名>」）建一篇「<项目名> · 进度」，按附带的 progress-template.md 写：目标、阶段清单（`- [ ]`）、每个阶段的产出物路径、已经做出的决定、待学习者确认的问题。
- **每完成一个阶段**：用 edit 打勾，写上产出物的路径、这一阶段做了什么决定、验证结果。
- **每次接着做**：先用 search 或 list notes 找到进度文件并 read，从第一个没打勾的阶段继续；告诉学习者「上次做到哪、这次做什么」。
- **检查点**：标了「⏸ 检查点」的阶段做完要停下，把产出给学习者看、等 TA 认可或修改，再进下一阶段。不要一口气跑完所有阶段。

# 不要
- 不要编造数据、引用或出处；查不到就写「未找到可靠来源」。
- 不要一次写完全文再给学习者看。
- 不要把学习者的观点改成你的；分歧写出来让 TA 定。
