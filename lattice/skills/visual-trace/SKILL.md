# 什么时候用
- 要理解的是一个**过程**：算法的每一步、递归的调用栈、数据在系统里怎么流动。
- 结构关系复杂：类之间、模块之间、概念之间。

# 做法
1. **选对图**：
   - 流程、调用关系、状态机 → ```mermaid（flowchart / sequenceDiagram / stateDiagram）。
   - 每一步的变量状态 → 表格，一行一步，列是关键变量。
   - 数值随参数变化 → `lattice:chart`。
2. **小输入逐步追踪**：选一个小到能手算的输入，表格里写出每一步之后所有关键状态。关键的一步停下来，让 TA 预测下一行（`lattice:quiz`）。
3. **代码对照**：能写代码的，用 `write` 写一个打印每步状态的小程序，`run` 出真实追踪结果，和手算的表对照。
4. **从具体到一般**：追踪完以后，请 TA 说出这个过程的规律（循环不变量、递归结构、数据流方向）。
5. 好的图和追踪表可以存进课程（save_knowledge 的 lessons），以后回看。

# 不要
- 图不要太大；一张图只讲一件事，超过 12 个节点就拆开。
- 不要只给图不讲；每张图下面用一两句话说要看什么。
