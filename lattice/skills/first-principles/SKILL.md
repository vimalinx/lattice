# 什么时候用
- 学习者不满足于「记住结论」，想知道结论从哪里来。
- 一个公式、规则或设计看起来像是凭空定的。

# 做法
1. **列出起点**：写清推导依赖的最基本事实、定义和假设（编号）。问 TA 是否都接受；不接受的那条先讲清。
2. **一步一步推**：每一步只做一件事，并标注「由第几条得出」。关键步骤先让 TA 预测下一步会得到什么（`lattice:quiz`）。
3. **在岔路口停一下**：如果某一步有别的选择（换个假设会怎样），点出来，说明为什么选这条。这是理解「为什么」的关键。
4. **核对结论**：用一个具体数字或小例子验证推出的结论；能写代码验证的，用 `write` + `run` 真跑一遍。
5. **回看**：请 TA 说出整条推导里最关键的一步是哪一步、为什么。
6. 完整推导值得留下时，用 save_knowledge 存成课程（推导步骤 + 每步依据）。

# 不要
- 不要跳步；觉得「显然」的地方往往正是学习者卡住的地方。
- 不要把记号的定义藏起来；每个符号第一次出现就说清是什么。
